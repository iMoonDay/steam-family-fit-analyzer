# UI 规范

## 视觉方向

- 界面以安静、清晰的桌面工具为目标，不做营销页、游戏皮肤或强装饰风格。
- 优先使用纯色背景和纯色面板，避免渐变、纹理、网格、发光、玻璃拟态等装饰。
- 色彩数量保持克制：中性色承担大部分界面层级，强调色只用于主要操作、当前状态和必要反馈。

## 布局与容器

- 保持工具型布局，优先使用侧栏、工作区、列表、分栏、状态栏等结构化区域。
- 不要默认让组件填满所有可用空间。表单、按钮、内容组和结果区需要根据阅读宽度设置合理的最大宽度。
- 工作区内容应保留适当留白，避免贴边、满屏拉伸和过密堆叠。
- 侧栏可以使用紧凑布局，但主要操作按钮不应无意义地被拉伸成整行。
- 不要过多使用卡片式设计。卡片只用于确实需要分组的独立内容，不把每个信息块都做成漂浮卡片。
- 不可交互的组件尽量不带背景色和外边框，优先通过留白、字号、分隔线和层级关系表达结构。
- 页面级区域可以贴边，但内容区内大部分带边框的容器需要使用圆角。
- 尽量少出现直角边。输入区、结果区、指标条、列表容器、按钮和交互控件默认应有圆角。
- 相邻的分段内容可以共享一个外层圆角，内部用分隔线表达结构，避免每个分段单独成卡片。

## 图标

- 所有图标必须使用 SVG。
- 禁止使用文本图标，例如 `?`、`×`、`□`、字母占位等作为图标。
- SVG 图标默认使用 `currentColor`，由按钮或容器状态控制颜色。
- 图标尺寸应稳定，不受字体影响；常规工具图标建议使用 14px 到 18px。

## 交互状态

- hover 和 active 状态保持轻量，不使用大面积高饱和背景。
- 主要按钮可以使用强调色；普通按钮和辅助操作优先使用 subtle/light 风格。
- 关闭等破坏性操作只在 hover 或确认状态下使用红色。
