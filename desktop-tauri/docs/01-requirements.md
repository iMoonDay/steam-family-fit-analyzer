# 需求边界与链路检查

## 输入

- Steam Web API Key：用于目标账号公开游戏库、当前账号 owned appids、Vanity URL 解析、玩家摘要。
- IsThereAnyDeal API Key：用于 Steam 史低价。
- 当前用户 SteamID64：用于判断当前账号已拥有的游戏。
- 家庭库数据：独立程序无法直接依赖 Steam 页面上下文，第一阶段建议用户粘贴 access token 或通过内置 WebView 登录后读取。
- 目标账号输入：SteamID64、好友码、个人主页 URL、自定义 ID。
- 本地配置：语言、商店地区、价格口径、列表视图、海报设置。

## 处理流程

1. 解析目标账号输入，得到一个或多个 SteamID64。
2. 拉取目标账号公开游戏库和玩家摘要。
3. 拉取当前账号 owned appids，用于排除已拥有游戏。
4. 拉取或读取家庭库。
5. 比对目标游戏、家庭库、当前已拥有游戏，得到新增、重复、无新增价值等列表。
6. 对新增候选游戏请求 Steam 商店条目，判断家庭共享支持性。
7. 按价格配置加载 Steam 原价或 Steam 史低价。
8. 渲染统计、表格、封面视图、对比视图，并支持复制报告和导出封面图。

## 状态变化

- 持久配置：API Key、语言、地区、价格口径、海报设置。
- 持久缓存：商店条目、本地化名、家庭共享支持性、原价、Steam 史低、封面 URL、封面 Blob。
- 非默认缓存：目标账号游戏库、当前账号 owned appids。它们变化会直接影响结果正确性，默认每次分析重新请求。
- 会话状态：当前报告、当前筛选、排序、滚动加载队列。

## 输出

- 分析摘要：目标游戏数、家庭库数量、新增数量、重复数量、新增价值。
- 游戏列表：全部、新增、重复、无新增价值、家庭库。
- 对比视图：多目标账号之间的差异。
- 复制文本：报告、当前列表、游戏名。
- 图片导出：家庭库封面图、当前列表封面图。

## 上下游影响

- 从脚本迁移为桌面端后，请求不再受页面跨域限制，但需要明确保存用户凭据的位置和权限边界。
- 家庭库读取是最大不确定点：脚本当前依赖页面登录态；桌面端需要新的登录或导入方式。
- 价格与封面缓存可以显著降低重复请求；目标库和当前 owned appids 不默认缓存，以保证分析结果不漏。

## 未验证前提

- Steam 家庭库接口在桌面程序中是否能稳定通过用户提供的 access token 调用，需要实测。
- ITAD API 的免费额度、批量限制和字段稳定性需要在实现阶段再次验证。
- Steam 图片 CDN 的跨域与缓存策略在 Tauri WebView 中需要实测。
