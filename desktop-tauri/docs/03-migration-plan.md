# 迁移计划

## 阶段 0：准备

- 冻结脚本当前能力清单。
- 为核心函数补最小测试：SteamID 解析、价格格式化、分类、排序、统计。
- 确认 Tauri、Rust、Node 版本和打包目标平台。

验收标准：不改业务行为，只得到可测试的核心逻辑边界。

## 阶段 1：抽核心

- 从 `script.user.js` 中抽出纯计算逻辑：
  - 账号输入解析。
  - 家庭库与目标库比对。
  - 家庭共享支持性分类。
  - 价格统计与排序。
  - 多目标对比。
- 使用 TypeScript 建模主要数据结构。

验收标准：给定 mock 输入，可以生成与脚本一致的报告对象。

## 阶段 2：桌面壳

- 初始化 Tauri 项目。
- 建立主窗口、设置页、分析页、列表页。
- 实现设置保存与读取。
- 跑通 Steam Web API Key + 目标账号分析。

验收标准：不依赖 Tampermonkey，可以在桌面窗口完成一次基础分析。

## 阶段 3：服务层

- 实现 Steam Web API client。
- 实现 Steam Store client。
- 实现 ITAD client。
- 统一错误类型：鉴权失败、限流、私密库、网络失败、数据格式异常。

验收标准：服务层返回标准化数据，核心层不感知第三方 API 细节。

## 阶段 4：缓存层

- SQLite 保存商店条目、本地化名、家庭共享支持性、原价、史低。
- 文件目录或 SQLite Blob 保存封面图片。
- 缓存按 `地区:语言` 分桶。
- 价格缓存按 `original` 和 `historyLow` 分槽。

验收标准：切换原价/史低不会互相覆盖；切换语言不会串用本地化名。

## 阶段 5：UI 迁移

- 迁移报告摘要、标签页、表格、封面视图。
- 迁移价格配置、语言切换、清缓存。
- 迁移列表菜单：复制报告、复制列表、复制游戏名、保存封面图。

验收标准：脚本已有的主要交互在桌面端都有对应入口。

## 阶段 6：导出与发布

- 迁移封面图导出。
- 增加导入/导出配置。
- 打包 Windows 版本。
- 写使用说明和隐私说明。

验收标准：用户无需打开 Steam 网页即可完成常规分析和导出。
